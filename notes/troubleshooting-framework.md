# Troubleshooting Framework

## Goal

I use the same process on every support ticket so issues get handled clearly and safely.

## Process

### Confirm the issue

Ask what the user is trying to do and what happens instead.

### Identify scope

Figure out whether it's one user, one device, one location, or multiple users.

### Check simple causes first

Examples:

- Power or cable connection
- Wi-Fi or Ethernet connection
- Account lockout
- Expired password
- Incorrect URL
- Service outage
- Full disk

### Make one change at a time

Changing a bunch of things at once makes it harder to know what fixed the issue.

### Verify with the user

The ticket isn't done until the user confirms the issue is resolved or the next step is clear.

### Document clearly

Good notes should include:

- Symptoms
- Environment
- Actions taken
- Results
- Escalation path if needed

## STAR-style support note

```text
Situation:
Task:
Action:
Result:
```

This format is also useful for interview answers.
